\subsection{Software summary}
\label{sec:Zellij:summary}

Exa-Zellij is a configurable implementation of two related families
for bounded continuous black-box optimization: Fractal-Based Decomposition
(FBD) and Fractal Bayesian Optimization (FBO). Both organize the decision
space as a hierarchy of self-similar regions. FBD allocates work through its
geometry and structural controls, whereas FBO uses a global objective-call
budget together with surrogate and acquisition information.

The FBD family exposes five independent runtime components:
decomposition geometry, exploration, scoring, tree search and exploitation.
The FBO family additionally exposes the initial design, surrogate and kernel,
acquisition-guided selection, budget allocation and exploitation strategy.
The effective configuration and actual evaluation count are reported for
every run.

The implementation retains this component-oriented philosophy while
making it directly usable as software: users select a family and its
components at runtime, supply a native, Python, batched, embedded-module or
executable objective, and keep the optimizer independent of application-side
simulation code.

\subsection{Purpose}
\label{sec:Zellij:purpose}

Exa-Zellij implements divide-and-conquer optimization through a
hierarchical decomposition of the search space. Autonomous child regions
expose independent objective evaluations, while a configurable selection rule
limits which regions continue to the next depth. The framework targets
high-dimensional and expensive objectives for which gradients are unavailable,
unreliable or too costly.

This software framework has been inspired by two distinct families of
decomposition-based optimization algorithms. The first one is based on
algorithms derived from Lipschitzian global optimization, such as DIRECT
and its various extensions (e.g. eDIRECT, BIRECT, HD-DIRECT). The second
one concerns metaheuristics based on fractal decomposition, such as
FRACTOP and FDA.

Four properties characterize the current Exa-Zellij implementation:
\begin{itemize}
\item \textbf{Generalization}: our goal is to build a framework which
unifies configurable FBD and FBO families in one runtime. The current
component matrix includes six decomposition geometries and interchangeable
exploration, scoring, tree-search, surrogate, kernel, budget and exploitation
choices.

\item \textbf{Modularity}: the framework must be as modular as possible,
so algorithms can be assembled from explicit components and objectives
can be replaced without editing the optimizer. Python callbacks, batched
callbacks, JSON configurations, executable adapters and embedded Python
modules expose the same optimization core.

\item \textbf{Massively parallel}: a transparent and efficient parallel
implementation uses MPI to distribute independent fractal work and
Kokkos to target CPU, NVIDIA CUDA and AMD HIP execution spaces. Scalar and
batched objective boundaries keep application evaluation separate from tree
selection and compact global reductions.

\item \textbf{Resilience and reproducibility}: depth-barrier checkpoints
retain the active regions, incumbent and surrogate archive. Checksummed
manifests, optional replicas, rolling generations, automatic restart and
elastic repartitioning across a changed MPI world size support recoverable
executions. The repository also provides deterministic seeds, tests, launch
recipes and result-verification material.
\end{itemize}

\subsection{Mathematics}
\label{sec:Zellij:mathematics}

Optimizing a non-linear, non-convex, derivative-free or black-box
function in a high-dimensional continuous search space is a complex
task. Commonly, we consider a minimization problem for an objective
function ${f: \mathcal{S} \subset \mathbb{R}^n \rightarrow \mathbb{R}}$:
\begin{equation}
\label{eq:minproblem}
  \hat{x} \in \arg\min_{x \in \mathcal{S}} f(x).
\end{equation}
Here, $\hat{x}$ is a global optimum, $f$ is the objective function, and
$\mathcal{S}$ is a compact set defined by constraints such as upper and
lower bounds on the search space.

FBD determines its number of evaluations from the selected geometry,
depth, beam, exploration and exploitation components. FBO instead receives a
global objective-evaluation budget and reports the actual evaluations consumed
by its initial design, tree exploration and terminal exploitation. This
distinction is part of the public configuration contract.
