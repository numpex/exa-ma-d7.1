\subsection{Parallel Capabilities}
\label{sec:WP3:Composyx:performances}


\begin{itemize}
    \item \textbf{Parallel Environment :} MPI+ threads and not fully assess MPI+StarPU for heterogeneous manycores.
    \item \textbf{Computation environment :} Distributed manycores (GENCI platforms, BSC), and GPUs (Jean-Zay, Adastra)
    %\item describe the parallel capabilities of the software
    \item \textbf{Scalability:} weak scalability on up-to $\approx$ 20~000 cores for the solution of a $\approx 10^9$ linear system. For GPU scaling with 512 GPU MI250x with 89\% efficiency.
    \item \textbf{Integration with Other Systems:} No integration into other Exa-Ma software yet.
\end{itemize}

\subsection{2026 advances}

\subsubsection{New developments}

New releases from version 1.4.1 at the end of 2025 to 1.7.1 in October
2026. The main new features are the support of GPU. CUDA support for
nvidia GPUs and more recently HIP for AMD GPUs were added,
benchmarked, and documented with tutorials.

\subsubsection{Scalability results with HIP}

In summer 2026 development for AMD GPU started, using HIP. The code
was then benchmarked on CINES's Adastra supercomputer. Notice that
\textbf{guix} is available of Adastra and HIP software stack, based on
open-source code from AMD was therefore quite easy to deploy.

\begin{figure}
  \centering
  \includegraphics[width=0.8\textwidth]{graphics/composyx/results_adastra_S.png}
  \caption{Composyx scaling on Adastra}
  \label{fig:composyx-adastra}
\end{figure}

On Figure \ref{fig:composyx-adastra} are the scaling results from 1 to
128 nodes. Each node has of 4 AMD GPU MI250x, with 2 \textit{Graphics
  Compute Die} (GCD) per MI250x, so we use 8 subdomains in total per
node. On the top of each bar is the number of iterations performed,
and on top of each graph is preconditioner type:

\begin{itemize}
\item \textit{0} for no preconditioner
\item \textit{AS} for Additive Schwarz
\item \textit{NN} for Neumann-Neumann
\item \textit{RR} for Robin-Robin
\item \textit{ASG+} for Additive Schwarz with additive Geneo
\item \textit{ASGd} for Additive Schwarz with deflated Geneo
\item \textit{NNGd} for Neumann-Neumann with deflated Geneo
\end{itemize}

We can see for Additive Schwarz an efficiency of 89\% from 1 node to
128.

\subsubsection{Scalability results with CUDA}

In 2025 development specific to nvidia GPUs was started. It continued
in 2026 and was benchmarked on the GENCI Jean-Zay supercomputer.

\begin{figure}
  \centering
  \includegraphics[width=0.8\textwidth]{graphics/composyx/results_jeanzay_S.png}
  \caption{Composyx scaling on Jean-Zay}
  \label{fig:composyx-jean-zay}
\end{figure}

On Figure \ref{fig:composyx-jean-zay}, we can see scaling results from
1 to 32 nodes, with 4 GPU v100 per node and one subdomain per GPU. We
can see for Additive Schwarz an efficiency of 88\% from 1 node to 32.
CUDA software stack is more complete than HIP's one. In particular,
the cuDSS library provides a sparse direct solver on GPU, which does
not have a counterpart for AMD where these type of computations have
to be made on CPU.

\subsubsection{Next steps}

GPU development and benchmarking is going on. We expect to have
results on the LUMI supercomputer to test scalability up to the limit:
1024 nodes, 4048 MI250x GPUs.

\paragraph{}

A new class to describe distributed matrices with more flexibility is
currently under development with the work of Arthur Gouinguenet. This
work will provide for the user a way to give an input matrix to
Composyx with his/her own distributed, dealing with degrees of freedom
potentially shared between subdomains. It will provide redistribution
of coefficients to adapt to specific format for other libraries. This
work was motivated by the application \textit{Hawen} where calls to
distributed solvers such as Mumps could benefit from this new approach
to describe matrices.
