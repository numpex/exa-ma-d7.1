\section{Reconstruction method and Sheet data-quality issue}
The live \emph{Benchmarks} tab was inspected on 23 July 2026.  Cell A1 returns
\texttt{\#REF!}: the array result cannot expand because it would overwrite C4.
C4 contains the literal ``CPU or GPU'' and I4 contains \texttt{TRUE}.  The broken
array was not copied into this report and the live workbook was not edited.  The
importable reconstruction is \texttt{data/benchmark-registry-v3.csv}; before a
future Sheet repair, the current tab should be exported, the blocking cells and
intended array formula reviewed with its owner, and the import applied to a
separate verified range or replacement tab.

Records below were reconstructed from the live Application metrics/scope/status,
the version-controlled specifications, the Demonstrator and Demonstrator tests
tabs, and observable repository files.  The Demonstrator tests tab provides no
completed V\&V record: all displayed non-regression, verification and validation
flags were \texttt{FALSE}.  A Sheet status such as ``benchmark-ready'' is
therefore not promoted to an evidence-based benchmark stage.

\section{Normalized registry}
Every record has exactly one application owner in this draft.  The CSV contains
the full normalized fields: owner and WPs, category and scope, repository and
commit, configuration, machine/resources, toolchain, baseline, scientific and
performance KPIs, repetitions, evidence, latest run, summary and limitations.
