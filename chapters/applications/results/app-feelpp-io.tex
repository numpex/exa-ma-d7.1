\paragraph{Faster sampling does not make storage faster.}
For a DG P0 tensor on 8.43~million cells and 256 ranks on Discoverer,
direct sampling cut warm EnSight preparation from 1.104 to 0.109~s,
while field packing and write moved only from 0.324 to 0.309~s.
The matched exports agree byte for byte, excluding the SOS launchers.
The gain is in preparation, not storage bandwidth.

\paragraph{Geometry, fields and reloading scale differently.}
At fixed mesh size, increasing from 256 to 2,048 ranks raised warm
rank-zero EnSight tensor packing and write from 0.309 to 0.417~s.
\Cref{fig:app-feelpp-io:scaling-by-operation} separates that cost
and the first geometry write from native HDF5 mesh and field save
and reload. The curves use one verified run per point and different
weak layouts. For moving meshes, measure geometry at the intended
output cadence rather than using the first static write as a proxy.

\begin{samepage}
\paragraph{The best writer depends on payload and layout.}
At 8.43~million cells and 512 ranks on Lustre, independent EnSight writes
raised median warm packing and write for the nodal tensor (0.123 to
0.247~s) but reduced it for the cell tensor (0.312 to 0.228~s) versus
rank zero. One of three independent cell repeats was slower.
Darshan observed four writing ranks for eight requested aggregators:
tune for the measured payload and actual writers.
\par\end{samepage}

\begin{samepage}
\paragraph{Reusing an HDF5 file amortizes repeated writes.}
On the 8.43-million-cell mesh at 512 ranks, writing six fields over
16 steps (16.43~GB of logical data) took 14.920~s with separate files
using independent transfers. Write wall time fell
to 3.985~s with one file and a flush every four steps. Exact coefficient
readback passed in both cases. The transfer mode is a separate choice:
the collective request was borne out for field writes in the probe,
but mesh writes remained independent. This does not establish a best
flush cadence or a cold-cache restart time.
\par\end{samepage}
