\textbf{Demonstrator: Reduced Basis Methods and Empirical Interpolation}

\label{sec:app:specs:app-feelpp-rb}

This demonstrator focuses on reduced basis methods and empirical interpolation techniques for parametric PDEs. These methods enable rapid solution of parametric problems by constructing low-dimensional approximation spaces from a set of high-fidelity solutions, making them essential for many-query scenarios such as optimization, uncertainty quantification, and real-time simulation.

\subsection{Description of the benchmark}

Reduced-basis methods separate an expensive offline construction from repeated
online evaluations of a parametric PDE. Greedy/POD basis construction, empirical
interpolation, full-order reference errors and output evaluation are the
scientific objectives of this application; achieved accuracy and speedup must
be established by an identified run rather than inferred from those methods.

\paragraph{Current implementation status.}
The \href{https://github.com/numpex/apps-feelpp/blob/main/src/app-feelpp-rb/rb_eye2brain.json}{Eye2Brain RB configuration}
requires \nolinkurl{feelpp_mor_eye2brain_3dP1app}, an executable that the
application repository does not build. The configuration is available;
executable readiness and benchmark validation have not been demonstrated.

The catalogue marks the application \texttt{benchmark-ready}, but the dashboard
does not report a completed \texttt{BM-FEEL-RB-01} campaign. The available
configuration selects Eye2Brain, not the earlier thermal-fin example.


\paragraph{Parameterized model and independent assessment.}
Let $R_h(u_h(\mu);\mu)=0$ denote the selected Eye2Brain full-order residual and
$s(\mu)=\ell(u_h(\mu);\mu)$ its declared output. The physical parameter ranges,
boundary/material laws and output functional must be attached to the model
CFG/JSON. Construct the reduced basis on an explicit training set, select
hyperparameters on a separate validation set, and assess state/output errors
on an independent held-out set. Archive seeds and sample lists. Report
full-order versus reduced error at fixed tolerances and distinguish snapshot,
basis/interpolation and online evaluation costs. The checked-in maximum basis
size 6, M3 mesh and 12 MPI ranks are launch settings, not accepted accuracy
or performance targets. Meshes, snapshots and reduced database revisions
must be recorded separately.

\subsection{Benchmarking methodology}

\paragraph{Protocol to validate.}
Identify the Feel++ MOR executable/build and adapt the configuration's absolute
executable path to the selected environment. Supply the Eye2Brain CFG/model,
parameter definition and partitioned mesh files; build or identify the reduced
basis database; then compare full-order and reduced outputs on independent test
parameters. Report the actual basis dimension, approximation errors, offline
cost and online timings with reconstruction/output costs stated separately.
A speedup compares like-for-like full/reduced evaluations at fixed accuracy;
it is not the ratio of offline construction time to online solve time.

The present configuration selects mesh M3, 12 MPI tasks and a maximum RB
size of 6. These are launch settings, not an accepted campaign result.
It requests journal timing stages and convergence files for FEM cost, $L^2$ and
$H^1$ errors and output error. The configured journal keys and resulting output
files must be checked against the chosen MOR executable before accepting a run.
Retain machine, toolchain/container digest, dataset and executable revisions,
training/test sets, repetitions and raw-data URLs.

\nolinkurl{cvg-crb-FemTime.dat}, \nolinkurl{cvg-crb-L2.dat},
\nolinkurl{cvg-crb-H1.dat} and \nolinkurl{cvg-crb-OutputError.dat}.

contents have not been verified for a current campaign.
