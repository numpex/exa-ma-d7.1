\textbf{Demonstrator: Preconditioning for Discrete Fracture Networks}

\label{sec:app:specs:app-hpddm-dfn}

This mini-application is intended to evaluate PETSc/HPDDM preconditioners for
linear systems arising from flow simulations in discrete fracture networks
(DFNs). Pre-assembled systems will allow solver robustness and parallel
performance to be studied separately from mesh generation and assembly.

\subsection{Description of the benchmark}

Depending on the physical model and discretization, DFN systems may present
the following challenges for linear solvers:

\begin{itemize}
\item \textbf{High aspect ratios:} Fractures are thin planar features embedded in 3D rock matrix, creating badly scaled systems
\item \textbf{Strong anisotropy:} Permeability contrast between matrix and fractures spans several orders of magnitude
\item \textbf{Network complexity:} Fractures intersect creating complex geometries and connectivity patterns
\item \textbf{Multi-physics coupling:} Flow in fractures coupled with matrix flow via source/sink terms
\end{itemize}

The planned benchmark will use identified DFN datasets from subsurface
applications to compare the following preconditioning strategies, where
applicable:

\begin{enumerate}
\item \textbf{Algebraic multigrid (AMG):} Hypre BoomerAMG and GAMG for comparison
\item \textbf{Domain decomposition:} One-level and two-level Schwarz methods via HPDDM
\item \textbf{Hybrid preconditioners:} Combining DD with coarse-grid correction
\item \textbf{Direct solvers:} MUMPS and PaStiX for comparison baselines
\item \textbf{Mixed-precision:} Exploiting lower precision for faster preconditioning
\end{enumerate}

The PETSc-native CPU/CUDA backend of \texttt{PCHPDDM} (HPDDM 2.4.0,
PETSc 3.25; \cref{tab:advance:WP3-A2026-2}) is a candidate for this study.
The coarse operator is still assembled and factorized on the host.
Subdomains shared by several MPI processes remain a prototype
(\cref{tab:advance:WP3-A2026-3}). Their integration and performance on DFN
systems remain to be validated.



\subsection{Benchmarking methodology}
\subsubsection{Benchmarking tools used}

PETSc event logging, convergence monitoring and post-processing will provide the following metrics:

\begin{itemize}
\item \textbf{Solver convergence:} Iteration counts, residual norms, convergence rates
\item \textbf{Time breakdown:} Preconditioner setup, application, Krylov iterations, communication
\item \textbf{Memory usage:} Per-processor memory footprint, sparse matrix storage
\item \textbf{Scalability metrics:} Strong and weak scaling efficiency, communication overhead
\item \textbf{I/O performance:} Matrix loading time, solution output time
\end{itemize}

Timings will be collected using PETSc's \verb+-log_view+ option; residual histories require KSP monitoring and an independent final true-residual check. Scaling efficiencies will be computed across runs by the analysis scripts. Export formats remain to be specified.

\texttt{BM-HPDDM-DFN-01} will compare configurations on identical systems
at fixed numerical acceptance criteria. Runs will record software revisions,
solver options, precision, hardware, MPI processes, threads and GPUs.
Setup, solve and transfer costs will be reported separately, with repeated
runs to assess variability.



\subsubsection{Preconditioner comparison}

No validated measurements are reported here. The following comparisons are
planned; results require identified datasets, configurations and raw logs.

The preconditioner comparison will assess:

\begin{itemize}
\item \textbf{AMG methods:} Measure convergence, setup and solve costs for HYPRE BoomerAMG and GAMG.

\item \textbf{One-level Schwarz (Additive Schwarz Method):} Measure iteration time and iteration-count growth with subdomain count.

\item \textbf{Two-level HPDDM:} Measure the effect of coarse-grid correction on convergence and scalability, including setup cost and its amortization over multiple solves.

\item \textbf{Direct solvers:} Use MUMPS and PaStiX as comparison baselines where memory permits; verify reference-solution accuracy, especially for ill-conditioned systems.

\item \textbf{Mixed-precision:} Compare supported precision configurations with an FP64 baseline, measuring memory, time, convergence, and solution error according to \cref{sec:app:specs:app-petsc-mixed-precision}.
\end{itemize}

\subsubsection{Strong scalability}

For a fixed, identified DFN problem (DFN-large, 10M unknowns):
\begin{itemize}
\item Measure speedup and parallel efficiency with two-level HPDDM
\item Track iteration-count growth for one-level methods
\item Quantify communication overhead as the process count increases
\item Compare CPU and CUDA configurations, including host work and transfer costs during setup and application
\end{itemize}

\subsubsection{Weak scalability}

For a documented problem sequence with controlled work (100k unknowns) per process:
\begin{itemize}
\item Track iteration counts for two-level HPDDM
\item Measure time per iteration and the contribution of coarse-grid communication
\item Report parallel efficiency relative to an identified baseline
\item Measure memory per process as the global problem grows
\end{itemize}

\subsubsection{Time-to-solution}

For each identified DFN problem at fixed residual and solution-error targets, report:
\begin{itemize}
\item Two-level HPDDM: setup and solve times, iteration count and resources
\item One-level Schwarz: setup and solve times, iteration count and resources
\item BoomerAMG: setup and solve times, iteration count and resources
\item MUMPS direct solve: factorization and solve times, memory use and resources
\end{itemize}

\subsection{Input/Output Dataset Description}


\subsubsection{Input Data:}
\begin{itemize}
\item \textbf{DFN geometries:} Three planned complexity levels, with different datasets and sizes:
  \begin{itemize}
  \item \texttt{DFN-small}: 50 fractures, 100k unknowns
  \item \texttt{DFN-medium}: 200 fractures, 1M unknowns
  \item \texttt{DFN-large}: 1k fractures, 10M unknowns
  \end{itemize}
  
\item \textbf{Linear systems:} Pre-assembled sparse matrices and right-hand sides in PETSc binary format from DFN flow problems. Document the equations, discretization, boundary conditions, symmetry, definiteness and nullspace treatment for each dataset; these properties determine suitable Krylov methods and preconditioners.

\item \textbf{Configuration:} Planned configuration files, with format to be confirmed, specifying:
  \begin{itemize}
  \item Preconditioner type and parameters, including partition, overlap, auxiliary operators, and local/coarse solvers
  \item Krylov method (GMRES, CG, BiCGStab)
  \item Convergence tolerance and maximum iterations
  \item Multi-precision settings (if applicable)
  \end{itemize}

\item \textbf{Reference solutions:} Reference solutions with documented residual and accuracy checks for error assessment
\end{itemize}

\subsubsection{Output Data:}

Planned outputs, with formats and export scripts to be confirmed:
\begin{itemize}
\item \textbf{Solution vectors:} Computed pressure/velocity fields in PETSc binary format

\item \textbf{Convergence data:} Iteration-by-iteration residual norms, convergence reason and independently recomputed final true residual

\item \textbf{Performance logs:} PETSc logs and, where used, external profiler outputs containing:
  \begin{itemize}
  \item Per-stage timing (setup, solve, I/O)
  \item Message counts, message lengths, and reduction counts
  \item Floating-point operation counts
  \item Cache performance metrics only if collected with a separately documented profiler
  \end{itemize}

\item \textbf{Scalability reports:} XML-formatted reports with:
  \begin{itemize}
  \item Time-to-solution vs. processor count
  \item Parallel efficiency curves
  \item Memory usage per processor
  \item Comparison across different preconditioners
  \end{itemize}
\end{itemize}

Metrics:
\begin{itemize}
    \item \texttt{strong-scalability}: Fixed problem size, varying processor count
    \item \texttt{weak-scalability}: Proportional problem size scaling
    \item \texttt{time-to-solution}: Total solve time for target tolerance
    \item \texttt{io-scaling}: Matrix load and solution write performance
    \item \texttt{relative-error}: Solution accuracy vs. reference
\end{itemize}
