\label{sec:app:specs:proposed}

Application planning follows the current operational status in

\subsection{Development Timeline}

Contributors should document the next milestone for each application according

and benchmarking, then validation and documentation. Dates and completed steps

\subsection{Notes on Status Definitions}

The application status describes operational maturity. The benchmark index
records the available evidence separately; readiness alone does not establish
completed validation or reproducible performance results.

\begin{itemize}
\item \textbf{brainstorming:} Initial concept phase, requirements not yet finalized
\item \textbf{spec-only:} Specification complete, implementation not yet started
\item \textbf{in-development / implementation-in-progress:} Active implementation ongoing
\item \textbf{prototype-ready:} A prototype is identified in the operational catalogue; its validation and benchmark evidence must be documented separately.
\item \textbf{benchmark-ready:} Operationally ready for systematic HPC benchmarking; completed validation and performance results require separate evidence.
\end{itemize}
