\subsection{Description of the benchmark}
Forward-performance benchmark: solve the nonlinear thermo-electric high-field-magnet model at fixed accuracy and expose state fields, nonlinear/linear solver behaviour, device residency and CPU/APU performance; no inverse or control objective is introduced in this application.
\paragraph{Scope boundary.}
This record covers only the shared forward operator.  Parameter inversion and
optimal control are separate applications.  The Sheet describes a future MI300A
campaign; this integration draft does not present that allocation or campaign as
a completed result.



\paragraph{Scientific baseline and configuration delivery.}
Use the shared HL-31 operator in
\Cref{sec:app:feelpp:shared-thermoelectric}, with identical geometry, material
laws, current loading and cooling on CPU and APU. A versioned toolbox CFG,
model JSON and native/container launch configuration are sufficient delivery;
new C++ is not a prerequisite. Backend availability and full device residency
must be checked for the selected discretization and solver stack.

\paragraph{Proposed comparison.}
First verify current/heat balance, peak temperature and field differences
against the CPU solution at predeclared tolerances. Fix mesh/order and nonlinear
and linear stopping tests, then compare elapsed assembly, solve and total time,
iterations, memory use and host/device transfers. State whether initialization,
JIT/setup, transfers and synchronization are included. Use repeated runs and
report variability, MPI/rank-to-device placement, native package version or
container digest. Multi-APU sweeps remain planned. Assembly/kernel experiments
are optional separate studies; they must not be substituted for an end-to-end
forward solve at fixed accuracy.

\subsection{Benchmarking methodology}


\paragraph{CPU reference and planned MI300A comparison.}
The \href{https://github.com/numpex/apps-feelpp/tree/main/src/app-feelpp-toolbox/thermoelectric/hifimagnet}{HiFiMagnet thermoelectric configuration}
provides the CPU reference case. The MI300A backend and launch configuration,
verification at matched accuracy, and performance measurements are still
pending for \texttt{BM-FEEL-MI300A-01}.
\paragraph{Planned contribution.} Pin the executable/config, input data, native and container environments,
MI300A topology, fixed-accuracy baseline, repetitions and raw-data location.
\begin{description}
  \item[Method-Algorithm WP1:] high-order cG/H1 and HDG, full/partial/matrix-free assembly, homogeneous worksets, facets, traces, coupled blocks, skeleton terms
  \item[Method-Algorithm WP3:] PETSc/HPDDM Krylov solvers, preconditioning, nonlinear and block solvers, device-resident sparse algebra
  \item[Framework:] Feel++, PETSc, HPDDM
  \item[parallel\_framework:] MPI, Kokkos, GPU - HIP, Multithread - OpenMP
  \item[Benchmark scope:] single-node, multi-node, multi-gpu, full-system, method-verification, solver-scaling
  \item[metrics:] forward-residual, discretization-error, fixed-accuracy, time-to-solution, time-to-precision, nonlinear-and-linear-iterations, assembly-cost, solve-cost, memory-residency, host-device-transfers, strong-scalability, weak-scalability, multi-APU-scalability
\end{description}
\paragraph{Planned contribution.} Review the proposed protocol and select the case-specific tolerances and parameter values before implementation.
