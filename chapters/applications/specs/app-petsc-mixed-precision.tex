\VThreeApplicationDraft{app-petsc-mixed-precision}
{Impact of mixed precision on PETSc solvers and preconditioners}
{P. Jolivet}
{WP3}{mini-app}
{Study performance, convergence and numerical accuracy effects of mixed precision in PETSc Krylov solvers and preconditioners.}
{PETSc, HPDDM, MUMPS; MPI and OpenMP}{implementation-in-progress}

\paragraph{Scientific objective and scope.}
This matrix-based mini-app will assess whether reduced precision in selected
solver or preconditioner stages decreases time-to-solution and
energy-to-solution while meeting prescribed residual and solution-error
tolerances. The baseline is a full double-precision solve of the same linear
system. The matrix suite and supported precision combinations remain to be
selected.

\paragraph{Relation to the 2026 developments.}
The PETSc-native CPU/CUDA backend of \texttt{PCHPDDM}, released with HPDDM 2.4.0
and PETSc 3.25, is described in \cref{tab:advance:WP3-A2026-2}.
It is a candidate execution path for this study; mixed-precision support
must be established for each selected configuration. CPU/GPU comparisons
will be reported separately from precision comparisons. Subdomains shared
by several MPI processes remain a prototype
(\cref{tab:advance:WP3-A2026-3}); no validation of that feature by this
application is reported here.

\paragraph{Inputs, outputs and validation.}
Planned inputs are matrices and right-hand sides in PETSc binary or Matrix
Market format, versioned solver options, and reference solutions with a
documented accuracy assessment. Each configuration will specify storage
and arithmetic precision for the operator, outer iteration, residual
evaluation, preconditioner, and local and coarse solves, as applicable.
Outputs will include the solution, convergence reason, iteration count,
residual history, phase timings and raw measurements.
Validation will independently recompute the true residual using the original
system in double precision and compare the solution with the reference.
Residual and solution-error thresholds will be fixed before benchmarking;
a small residual alone will not be treated as evidence of small solution
error. Failed or stagnating solves will also be reported.

\paragraph{Benchmark contract.}
\texttt{BM-PETSC-MIXED-01} will compare supported precision configurations
on identical inputs and resources at the same numerical acceptance targets.
Timings will separate setup, solve, precision conversion and host/device
transfer costs, with the end-to-end measurement boundary stated explicitly.
Scaling studies will record matrix size, partition, MPI processes, threads
and GPUs, where applicable. Energy-to-solution will be reported only with a
documented instrument, sampling method and CPU/GPU/node coverage, using the
same measurement interval as time-to-solution. Repeated runs will report
variability.

\paragraph{Maturity and next steps.}
The application remains \texttt{implementation-in-progress}; no measured
performance, scalability or accuracy results are reported here.
Next steps are to publish the executable and configurations, version the
matrix suite, validate the supported precision combinations, and run the
benchmark campaign.
